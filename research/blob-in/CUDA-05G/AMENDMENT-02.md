# CUDA-05G-P01 amendment 02 — invalid measurement instrument, not a finding

The second acquisition used the cached `postgres:16` image and passed ownership setup. Its server was confirmed under host UID 65534, but the positive controls received Python `OSError: None`. Root cause: the *host-visible* Unix socket pathname constructed under the long evidence output directory exceeded the Linux AF_UNIX `sun_path` maximum (107 pathname bytes). The Docker client saw the much shorter mount path `/lab/experiment.sock` and could connect. The protected-directory outsider reported that it could not read `/lab/client.pl`, **not** that it was denied a socket connection; the negative control was therefore invalid. The finite service had not completed before the harness removed its container. **No gates are marked PASS.** Raw data is retained outside the public source tree.

Before a third acquisition, stage only the temporary socket under the host's short system temporary directory (`/tmp`), explicitly fail closed if its filesystem socket pathname exceeds 107 encoded bytes, and invoke the DAC-negative client via `perl -e` from the image rather than reading a script under the very directory whose access is being challenged. The pre-registered four-attempt, three-accept protocol and all permission/identity gates remain unchanged. The runner will also record whether the server actually exited before cleanup instead of inferring a clean exit from a Docker inspect call alone.
